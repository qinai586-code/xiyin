# arch-01 结果与修复路线（2026-09-28）

**结论：** 提示层和运行时层能调的东西，已经没有能让失败减半的了。
arch-01 里有效的三个臂都没有达到预先写定的门槛。第四个臂（思考模式）因为我设的预算不对而无效。

本文数字都是正则提示，加上我直接读样本（不是盲评）得出的。

思考臂里还有一个值得记下的现象：模型在“思考”中拟的草稿，结尾照样是反问，例如“你当时发现的时候，肯定挺意外的吧？”。抛回话头的习惯在它考虑措辞的阶段就已经存在。

**给真实记录后的问题（H1）。** 她会用记录，但守不住证据边界：
- **添油加醋**：“查了查他的习惯记录，发现他那天其实是在整理旧档案”，这件事记录里没有，是编的。
- **张冠李戴**：把主理人的消息说成是“祈奈在某个深夜发来简短消息”。
- **认不出对面就是主理人**：当面对你说“上次听主理人说盐放多了”，把“主理人”和“你”当成了两个人（E-02）。
- **硬塞**：被问“你是谁”时，扯到番茄炒蛋上。

## 2. 汇总到现在的证据

- 提示层面已经试过 15 种以上的变化，“抛回话头”一直在 0.61–0.73 之间：
  - V1–V5 五种投影；
  - ceiling-02 的四项消融；
  - persona-01 的三个开关臂；
  - arch-01 的三个有效臂。
- 编造的形态会换，比例几乎不降。把“机器腔”压下去，就冒出“人类生活腔”；给了素材，就在素材上加工。
- 9B 和 4B 的失败方式相同。

外部研究的方向与此一致（检索结果，arXiv 原文受网络限制未能打开）：
- **“助手轴”**：指令模型的默认助手人格对应激活空间里的一个主方向，人格会沿着它漂移。只靠提示很难把模型从这个方向上拉开。Anthropic 等 2026 年 1 月的研究用“激活上限”把漂移造成的有害回答减少了大约一半。
- **人格向量**：谄媚、幻觉、冷漠等特质在激活空间里有对应方向，可以监测，也可以加强或抑制。验证过的模型是 7–8B。
- **提示不如训练**：多项研究表明，要让语气和人格稳定，微调（包括 LoRA）比系统提示有效；超长的提示反而会降低小模型的生成质量。

## 3. 诊断

1. **主因：模型层面。** 小型指令模型自带的“助手默认值”和“编补细节”倾向，提示改不动，这 15 次以上的尝试都证实了。
2. **次因：架构层面，可以修，但修了也不够。**
   - 记录用第三人称写“主理人……”，而她正在和主理人本人说话，导致张冠李戴；
   - 语义层面的编造没有判官能抓到，默认模式下直接放出；
   - 重试时用的是同一组消息。

## 4. 修复路线（全部本地，不上云）

| 步骤 | 做什么 | 是否算训练或改模型 | 回答什么问题 |
|---|---|---|---|
| **S1 本地大模型对照（推荐先做）** | 用 Qwen3.5-27B（Q4 约 16GB，部分放到内存）在本机跑同一套 persona01 和盲评 | 不训练，不上云；只是速度慢 | 你的判断“只有大模型才行”对不对。27B 通过，说明架构没问题，缺的是模型；27B 也失败，说明问题在规格或架构本身 |
| S1b 思考模式重测 | 用 llama.cpp 的 `--reasoning-budget` 把思考限制在 256–512 token，只重跑这一臂 | 否 | 短暂思考是否有帮助，以及代价是多少延迟 |
| S2 架构小修 | 私聊时把关于主理人的记录改成用“你”来称呼；重试时附上被拒原因 | 否 | 减少张冠李戴；不会解决主因 |
| S3 激活引导（控制向量） | 用对比提示算出“助手腔”方向，推理时反向施加；llama.cpp 原生支持 `--control-vector` | 不改权重、不用训练数据；但属于模型层干预，需要你批准 | 能否不训练就把模型从助手默认值拉开 |
| S4 LoRA（有 S1 结果后再定） | 让 27B 在本地离线生成候选对话，由你筛选，再微调 4B/9B（蒸馏） | 是训练，需要你批准；数据不用我写，避开条款问题 | 小模型能否学会大模型的表现 |

建议的顺序：S1 + S1b 放在同一次 Windows 运行里 → 根据结果决定 S3 或 S4，或者直接用 27B（如果延迟可以接受）。S2 可以随时做。

**需要主理人提供：** 电脑的内存大小（27B 部分放到内存需要 32GB 或以上）；是否已有，或愿意下载 Qwen3.5-27B 的 GGUF。
