# steer-01 分析：控制向量没有失败，是生成工具被卡住（a22c742，2026-09-28）

**结论：控制向量没有被测到，不能判定失败。** 生成工具 `llama-cvector-generator` 与 Qwen3.5 的模型结构不兼容，在处理第一对样本时就因断言退出。方法本身的效果仍是 **NOT VERIFIED**（未验证）。

## 1. 证据

- **断言：** `cvector-generator.cpp:221: GGML_ASSERT((int) diff_filtered.size() == n_layers - 1) failed`。用单行合成输入也能复现，和样本内容无关。
- **原因：** Qwen3.5-4B 的 GGUF 文件里有一个多 token 预测层（MTP/nextn）。服务器日志里 `blk.32.nextn.*` 被标为 “unused tensor”，推理时不会运行。
  - 工具用 `llama_model_n_layer()` 读到的层数是 33，其中包含这一层；实际计算的只有 32 个真实层。
  - 工具只采集宽度完整的 `l_out`。最后一个真实层因为只保留输出行，不会被采集。
  - 所以实际采到 31 层，工具却按 33 − 1 = 32 层来检查，断言失败。
- **服务器端没有问题：** llama.cpp 主线的 `src/models/qwen35.cpp` 在每个真实层都会调用 `build_cvec(cur, il)`，只遍历这 32 层。所以只要生成出向量，服务器就能施加。这一点针对的是主线代码；你本机的 b11062 构建上还需要实测确认。
- **问题本身再次被证实：** 这次运行新测的 4B 基线（52 轮 × 4 个样本）：
  - 客服腔 0.731，其中抛回话头 0.721；
  - 编造类 0.322，硬提示 0.135。
- **对比样本质量合格：** 从 23 轮上下文里采到 45 对。“干净”和“客服腔”的差别确实主要在结尾：是否反问，是否主动提出“要不要我帮你……”。
